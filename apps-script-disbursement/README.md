# مسمار — بيانات صرف الفواتير (Disbursement Data for Looker) · v1.2

سكربت **مستقل** عن سكربت التدقيق. يسحب فواتير التكلفة B2B **بالجملة** (مثلاً كل
المسددة لسنة 2026، أو غير المسددة) إلى تبويب واحد **«بيانات الصرف»** لتفلتره في
**Looker Studio** — **مع إضافة رقم اللوحة** الذي لا يظهر في صفحة التكاليف.

## ضمان صحّة البيانات (أهم نقطة)
- **كل فاتورة تكلفة = صف واحد** (المفتاح = رقم الفاتورة، upsert).
- **لا حذف تكرارات للسيارات**: سيارة اتعملها صيانة مرتين → فاتورتان → **صفّان**. لا
  نجمعهم أبدًا. التكرار الوحيد الممنوع هو تكرار **نفس الفاتورة** (إعادة التشغيل تحدّث
  الصف مكانه بدل تكراره).
- المبلغ يُخزَّن كـ**رقم**، والتواريخ كنص ISO `YYYY-MM-DD`، مع عمودَي **السنة**
  و**الشهر** — جاهزة لفلترة Looker.

## آلية العمل
1. يجلب من `GET /adminApi/v2/orders-cost-invoices` بمعاملات الأدمن **المؤكّدة**:
   ```
   ?businessOrderTypes=B2B_business
    &fromPaidDate=YYYY-MM-DD &toPaidDate=YYYY-MM-DD   ← تاريخ الصرف من/إلى
    &status=1                                          ← حالة الدفع (1=تم الدفع)
    &purchaseLocationsIds=..  &spendSupplierIds=..     ← مكان/مورد الصرف (بالـID)
    &offset=.. &limit=100 &page=..
   ```
2. **وضعان (اختيارات):** `paid` (المصروفة ضمن تاريخ الصرف) · `unpaid` (غير المصروفة).
   الاثنان يتراكمان في نفس التبويب مع عمود **«الوضع»** للتمييز.
3. **رقم اللوحة** يُجلب من داخل كل طلب (`/adminApi/v1/orders/{id}`) — أرقام + حروف
   مثل `3039 ا س ط`.

## السحب السنوي (كبير) + الاستئناف
جلب اللوحات مكلف (طلب لكل أوردر) والحدّ 6 دقائق. لذلك:
- **كاش دائم للّوحات** (`__plate_cache` مخفي): كل أوردر يُجلب **مرة واحدة للأبد**.
- التشغيل **قابل للاستئناف**: كل تشغيلة تكمل ما تبقّى.
  1. **▶ سحب / تحديث البيانات** — يجلب الفواتير ويحدّث الصفوف، ويبدأ اللوحات.
  2. **🚗 إكمال جلب اللوحات** — كرّرها حتى تصبح «لوحات ناقصة = 0».
  3. أو **⏰ تفعيل التحديث التلقائي** — تريغر كل 10 دقائق يُكمل اللوحات ثم يحدّث.
- الصفوف بلا لوحة بعد تُلوَّن برتقالي حتى تكتمل.

## حالة الدفع (status)
`1 = تم الدفع` (مؤكّد) · `2 = غير مدفوعة` · `3 = الدفع بالأجل` (يُرجى التأكد).
وضع `paid` يجلب `1,3` افتراضيًا (قابل للتغيير من الإعدادات).

## أعمدة «بيانات الصرف»
`رقم الفاتورة · رقم الطلب · رقم اللوحة · مكان الصرف · مورد الصرف · نوع الصرف ·
المبلغ(رقم) · تاريخ الصرف · السنة · الشهر · تاريخ الاستحقاق · تاريخ الفاتورة ·
حالة الدفع · الوضع · مطابقة التاريخ · آخر تحديث`

## Looker Studio
الاستخراج **لا بدّ** أن يظل بالسكربت (Looker لا يستطيع مناداة API مسمار ولا جلب
اللوحة). التسلسل:
```
Apps Script → تبويب «بيانات الصرف» → Looker Studio
```
- Looker Studio → **Create → Data source → Google Sheets** → اختر هذا الملف
  وتبويب «بيانات الصرف».
- افلتر بـ السنة/الشهر/الوضع/المركز/المورد/حالة الدفع، واجمع «المبلغ».

## طريقة التركيب
1. أنشئ **Google Sheet جديد** (منفصل عن ملف التدقيق).
2. **Extensions → Apps Script** → الصق `Code.gs` (واختياريًا `appsscript.json`) → احفظ.
3. أعِد تحميل الشيت → قائمة **«بيانات الصرف»**.
4. **🔐 حفظ التوكن** ثم **⚙ إعداد الشيت أول مرة**.
5. للسنة المسددة: الوضع `paid`، التاريخ `2026-01-01 → 2026-12-31` (مضبوطة مسبقًا).
6. **▶ سحب / تحديث البيانات**، ثم كرّر **🚗 إكمال جلب اللوحات** حتى تكتمل — أو فعّل
   **⏰ التحديث التلقائي**.
7. اربط **Looker Studio** بتبويب «بيانات الصرف».

## ⚠️ نقاط بسيطة تحتاج تأكيدًا
- `status=3` للأجل — تخمين؛ عدّل خانة «حالات الدفع» لو مختلف.
- `spendSupplierIds` لفلترة المورد بالـID — تخمين؛ الفلترة **بالاسم** تعمل دائمًا.
- أسماء حقول عناصر `raw` (المبلغ/المورد/النوع/تاريخ الصرف) بمرشّحات مرنة.
> بديل مضمون 100%: الصق كامل كويري بحث الأدمن في `RAW_QUERY`.
> ولو أرسلت لي عنصر `raw` واحدًا + JSON طلب، أثبّت كل الحقول واسم اللوحة نهائيًا.
